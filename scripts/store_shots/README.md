# App Store スクリーンショットの作り方

素のキャプチャを `スナップショット/raw/<iphone|ipad>/` に置いて、

```bash
python scripts/store_shots/compose.py
```

を走らせると、`スナップショット/store/<iphone|ipad>/` に見出し付きの画像ができる。
出力サイズは iPhone 6.9" (1320x2868) と iPad 13" (2064x2752)。
キャプチャした端末のサイズは問わない (枠の中に縮めて置く)。

どの画面を・どの見出しで出すかは `shots.json`。`src` のファイルが無い行は飛ばす。
App Store は端末ごとに 10 枚まで。

## Apple の決まり

- スクリーンショットは「アプリを使っている様子」でなければならない (審査ガイドライン 2.3.3)。
  端末の枠や見出しの文字を足すのは認められていて、ストアの大半のアプリがこの形。
- 駄目なのは、起動画面やログイン画面だけ、アプリに無い機能を描く、本物と違う UI を載せる、の類。
- 名前や @ID のモザイクは問題ない。ただし画面の大半を潰すと「壊れた UI」に見えるので、
  隠すのは名前・@ID・本文の一部にとどめ、できればテストアカウント同士の画面で撮る。

## 撮るもの (shots.json の順、iPhone 10 枚)

| # | name | 開く画面 | 状態 |
|---|---|---|---|
| 1 | timeline | ホーム (統合タイムライン) | X と Bluesky の投稿が混ざっている。画像付きが 1 つあるとよい |
| 2 | accounts | アカウント一覧 | X と Bluesky が混ざった実際の並び |
| 3 | compose | 投稿画面 | 本文を入れ、アカウントを 1 つ選び、画像を 1 枚付けた状態 |
| 4 | engage | 投稿詳細 + いいねのアカウント選択シート | |
| 5 | notifications | 通知 (すべて) | フォロー・いいね・リプライが混ざっている |
| 6 | likes | いいね・ブックマーク一覧 | 数件入っている |
| 7 | follow | フォロー/フォロワーの対象画面 | 数字のカードが埋まり、履歴が数件ある |
| 8 | follow_diff | フォロー/フォロワーの差分画面 | 増えた人・減った人が両方いる |
| 9 | blockscan | つながり調査の結果画面 | 完了した調査で、ブロック・ミュートの件数が出ている |
| 10 | customize | 設定 (外観) | |

iPad は 1・2・5・7・9・10 の 6 枚。
入れ替え候補: DM 一覧、ユーザー検索、投稿の作成日/誕生日の画面。

## 撮るときの約束

- ダークテーマで撮る。背景が暗いので、ライトだと浮く。
- ステータスバーは Wi-Fi・満充電の状態で。時刻は気にしなくてよい。
- 読み込み中の輪・空のリスト・「新しい投稿」のバナーが映っていないか確認する。
- iPhone はどの機種でもよい。iPad は 11 インチ級で撮れば 13 インチ枠に収まる。

## 名前と @ID を隠す

`shots.json` の行に `mosaic` を足す。単位は素のキャプチャの px、`[x, y, 幅, 高さ]` の並び。

```json
"mosaic": [[290, 500, 400, 100], [290, 720, 400, 100]],
"mosaic_block": 24
```

`mosaic_block` はモザイクの粗さ (省略時 24)。
座標は画像ビューアで読むか、キャプチャを置いて Claude に「ここを隠して」と頼めば書き込める。

## 見出しを直す

`shots.json` の `title` (2 行まで。`\n` で折る) と `subtitle` (1 行) を書き換えて走らせ直す。
句読点は行頭に来ないよう自動でぶら下げる。
